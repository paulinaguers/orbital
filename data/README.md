# data/

> **Simulated data – not real astronaut data.**

> **AI use:** cases, generator and this file drafted with Claude Code (Opus 5.5) from the team's skills; clinical criteria and review by The Foxhole Court.

## clinical_test_cases.csv

**What it is.** A test dataset for one fictional astronaut (`SIM-01`, 188 flight days) that exercises every alert level and the main threshold boundaries (just below, at and just above each cut) of the 10 MVP measurements. Each row carries the level the core should return, written by hand from `docs/content/alert_texts.md` and the team's `fisiologia-espacial` skill. Thread A's core tests can use it as the answer key.

It is **not** a realistic mission timeline: every measurement is daily on purpose, and radiation jumps in its last block. The realistic demo simulator is a separate task (thread A).

**How to regenerate** (from the repo root):

```bash
python -m backend.simulator.generate_clinical_test_data
python -m pytest backend/tests -q
```

The cases live in `backend/simulator/clinical_cases.py`; values and expected levels are written there by hand. If a threshold changes, update the cases there and regenerate. The fixed seed only shuffles the order of the baseline days, so every run gives the same file.

### Layout

| Flight days | Block |
| --- | --- |
| 1–3 | No baseline yet: only clinical thresholds apply|
| 4–10 | Baseline days|
| 11–177 | Single-day cases (alternating measurements) and multi-day sequences, with separator days|
| 178–188 | Radiation (last, because the dose can only go up)|

Every column that a row does not test stays at its baseline mean (radiation rises 0.5 mSv per day, an arbitrary simulated rate).

**Baseline formula:** mean and `statistics.pstdev` (population standard deviation) of flight days 4–10. Proposed by thread C on 14/11/2026, to confirm with thread A; it must match the core's `baseline.py`.

### Columns (43)

| Columns | Meaning|
| --- | --- |
| `flight_day`, `timestamp`, `astronaut_id`, `simulated` | Day 1–188, fictional date, `SIM-01`, always 1|
| `blood_pressure_systolic_mmhg`, `blood_pressure_diastolic_mmhg`, `heart_rate_bpm`, `spo2_pct`, `glucose_mg_dl`, `sleep_hours`, `mood_vas_score`, `pvt_lapses` | Measurements with units. `mood_vas_score` is 0–100 with 100 = worst|
| `vision_amsler` | `no_change`, `change_not_repeated`, `change_awaiting_retest`, `change_confirmed`, `sudden_loss_or_distortion`, `area_growing` |
| `cabin_co2_7d_avg_mmhg`, `cabin_co2_1h_avg_max_mmhg` | CO₂ 7-day average and highest 1-hour average of the day, given row by row as the habitat would report them (the 7-day value jumps between rows on purpose; it is not recomputed from earlier rows)|
| `radiation_dose_cumulative_msv`, `solar_particle_event` | Cumulative dose (mSv) and solar storm in progress (0/1)|
| `symptom_dizziness`, `symptom_lightheaded_or_faint`, `symptom_headache`, `symptom_cold_sore_or_rash` | Self-report checkboxes (0/1)|
| `case_id` | Test case (`BP-01`, `HR-S4`, …); `BASE-` baseline days, `SEP-` separator days|
| `expected_level_<measurement>` | Final level the core should return|
| `expected_clinical_level_<measurement>` | Level of the fixed clinical layer only; `n/a` for mood and PVT|
| — | On days 1–10 the final level of mood and PVT is also `n/a`: no clinical layer and no baseline yet|
| `note` | Source of the threshold, *Proposal* marks and, for `PENDING`, the open decision|

**Levels:** `green`, `yellow`, `orange`, `red`, or `PENDING` when the level depends on an open team decision (named in `note`; the list is `DECISIONS` in `clinical_cases.py`). Tests of the core should skip `PENDING` cells.

## Demo scenarios

> **Simulated data – not real astronaut data.**

**What it is.** 42 continuous flight days of one fictional astronaut (`SIM-02`, Alex Rivera), in 4 scenarios (one per alert level), so the trend charts tell a story. Generated by `backend/simulator/demo_scenarios.py` (seed 2031); the levels are not in the file: the core computes them. The core and the API always **read this CSV** through `backend/storage.py`, so editing it changes what the app shows. `python -m backend.export_demo` writes `frontend/src/data/demo.json` (backup for the screen); `uvicorn backend.api.main:app --reload` serves the same data live.

| Scenario | Story| Day 42|
| --- | --- | --- |
| `healthy` | Everything in the usual range| green, no alert on any day |
| `deterioration` | From day 33 cabin CO₂ rises, sleep shortens (6.4–6.9 h), the PVT on day 38 is worse and fatigue rises to 5/10| yellow: sleep, CO₂, PVT, fatigue |
| `attention` | Deterioration + resting HR 66–67 bpm on days 40–42: clinically normal, but a sustained marked deviation from Alex's own baseline| orange: heart rate (personal baseline); sleep and CO₂ yellow |
| `emergency` | Deterioration + nights under 6 h on days 41–42, SpO₂ 89 % and headache on day 42| red: SpO₂, sleep; CO₂ orange |

**Schedule:** vitals, sleep, CO₂, radiation and check-in every day; PVT on days 4, 6, 8, 10 (practice, baseline) and then every 4 days; Amsler weekly (days 5, 12, …, 40). Mood, fatigue, stress and workload use the 0–10 scale (10 = worst) and are four separate indicators with a baseline layer. Radiation rises 0.5 mSv/day (arbitrary simulated rate).

**Baseline days:** on days 4–10 each vital is spread like the rest of the mission (offsets −1.5 to +1.5 × its daily spread). With 7 purely random days the baseline can come out too narrow by chance, and then normal days trigger false deviation alerts: an open point for the team (minimum spread or a longer baseline).
